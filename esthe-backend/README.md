# エステ営業 営業ノート — Pages / GAS API 移行

現状: コード準備済み。本番切替・実環境の通信テストは未完了。

## 構成と変更

- `pages/index.html`: 既存画面を再利用。埋込店舗データを除去し、Googleログインとfetch通信へ変更。
- `pages/api.js`: POST・JSONレスポンス、タイムアウト、認証期限切れの処理。トークンはメモリ内のみ。
- `pages/config.js`: 公開可能なAPI URLとOAuthクライアントIDを一箇所で管理。
- `gas-api/Api.gs`: actionの許可リスト、Google署名検証、アカウント制限、JSON応答。
- `gas-api/Business.gs`: 既存取得・保存ロジックを維持。スプシIDをScript Propertiesへ移動。認証済み操作アカウントを記録に追加。
- 許可メールはGASのScript Propertiesで設定し、公開リポジトリには置かない。
- `gas-api/JwtLibrary.gs`: jsrsasign。署名検証用、ライセンス同梱。
- `build.py`: 既存HTMLと業務ロジックから移行用ファイルを生成。元の本番ファイルは変更しない。

## 設定と公開

1. 既存GASとは別のプロジェクトを作成し、gas-api内のgsファイルとappsscript.jsonを配置する。
2. まずテスト用スプシのコピーを用意する。GASのプロジェクト設定のScript PropertiesにSPREADSHEET_ID、GOOGLE_CLIENT_IDを設定する。
3. ALLOWED_EMAILSを許可するメールアドレス1件のJSON配列に設定する。後から追加する場合もサーバー側のみで変更する。
4. Google Cloudでウェブ用OAuthクライアントを作成。承認済みJavaScript生成元に実際のPagesのオリジンを登録。クライアントシークレットはフロントに置かない。
5. 新しいGASウェブアプリを所有者として実行、アクセスを全員にしてデプロイ。データ操作には別途API内のGoogle認証・許可リスト検証が必須。旧HTML版のデプロイは変更しない。
6. /exec URLと公開OAuthクライアントIDをpages/config.jsに設定する。
7. GitHub sanochin48-stack/todo-app のesthe/へpages内のみを配置。既存Pagesのブランチ・公開元を維持。元のリポジトリ履歴、seed.json、app-code.txt、スプシIDを公開しない。

## 必須の実機確認（未実施）

PCとスマートフォンからPagesを開き、Googleログイン、データ取得、検索、架電記録の新規保存、TEL日・進捗更新、スプシへの反映を確認する。分岐を複数回選んだ後の戻る・アポへの遷移、県別・スクリプト版別・5件比較も確認する。

許可外アカウントの拒否、認証期限切れ、ネットワーク切断、タイムアウト、保存再試行、同一店舗の更新競合も確認。通信はtext/plainのPOSTでプリフライトを避け、リダイレクト先のJSONを読む。実際のGAS CORS動作は公開URLで確認する必要がある。no-corsでは代替しない。

既存アプリに店舗の新規登録・削除機能はない。今回の新規登録は架電記録、更新はリストのTEL日・進捗を指す。

## 切替・復旧

旧コードの復旧点はbackup/gas-before-pages。別GASプロジェクト間ではLockServiceの排他を共有しないため、旧版と新版から同時に書き込ませない。

テスト用コピーで全項目確認後、全端末の保存を一時停止し、新APIのSPREADSHEET_IDを本番へ変更。新版から確認し、全端末を新URLに統一してから運用再開。旧版は書き込み停止またはデプロイを無効化する。復旧する場合も両方の保存を停止してから旧版に統一する。

## 更新方法

画面変更はesthe/のHTML・JSをGitHubに反映しPagesの公開完了を確認。画面だけの変更ならGASの再デプロイは不要。

GASコード変更は「デプロイを管理」から新APIのデプロイを編集し、新しいバージョンを選び更新する。同じデプロイを更新すれば/exec URLを維持できる。Script Propertiesだけの変更は再デプロイ不要。スクリプトや県リストのシート追加も再デプロイ不要。

## 検証の区分

ローカル: JWT署名・期限・許可外アカウント拒否、通信のタイムアウト処理、既存の記録保存・重複防止・競合・分岐・集計の自動テスト。

未完了: 公開PagesとGAS間の実通信、スプシへの実書込み、PC/スマホの実画面、本番切替。ローカルの通信テストはモックでありCORSの実証ではない。
